## 4. Engineering decisions log (ENG, chronological)

- E-001 (2026-10-26) Maven Central returned HTTP 429 through the shared egress; Google's public Maven
  Central mirror is listed before `mavenCentral()` in `settings.gradle.kts`. Reversible.
- E-002 (2026-10-26) No `/dev/kvm` in the build container, so the Android emulator cannot run here;
  Robolectric is used for JVM-hosted Compose interaction tests and labeled accordingly.
- E-003 (2026-10-26) Lint suggests merging `mipmap-anydpi-v26` into `mipmap-anydpi` (minSdk 26), but AAPT then
  fails to resolve the adaptive launcher icon in this toolchain; the `-v26` folder is kept and the lint warning
  is accepted.
- E-004 (2026-10-26) Room naming/renaming is inline on the screen rather than in a modal dialog (also avoids a
  Robolectric idling problem with text fields inside dialogs). Plan view controls sit in a toolbar outside the
  canvas so they never cover geometry (I-05). Wall length labels are drawn 32 dp outside the wall (I-06).
- E-005 (2026-10-26) Startup media revalidation deletes unregistered media bytes (interrupted recordings) and marks
  registered media with missing bytes as unavailable.
- E-006 (2026-10-26) **Supersedes the D-05 default behaviour for exact wall lengths** (engineering default, reversible;
  the start corner is still anchored): typed lengths now default to *Keep corners square*, which slides the next
  wall along the edited wall's direction so every corner angle is preserved. The original "move the far corner only"
  remains available via a toggle. Reason: persona walk-through and review research (docs/BUILDER_UX_RESEARCH.md)
  showed the far-corner rule turns a rectangle into a trapezoid as soon as one real measurement is typed.
- E-007 (2026-10-26) Drag snapping engine (`domain/edit/Snap.kt`): room-axis angles in 45° steps with 4° tolerance,
  exact corner when both arms lock, ½" / 1 cm length steps for drags only, corner alignment, 14 dp screen tolerance,
  haptic tick on engagement. Typed values bypass snapping. Tuning still needs device verification.
- E-008 (2026-10-26) In feet mode, two bare numbers mean feet then inches (`11 6 1/4` = 11' 6 1/4"); metric mode
  still refuses ambiguous bare pairs. Inputs show a live interpretation before committing.
- E-009 (2026-10-26) After a typed (non-drag) edit, the plan view refits if any corner leaves the visible canvas.
- E-010 (2026-10-26) **Owner instruction:** the 2D builder must be fully usable without scrolling. Implemented with a
  non-scrolling step bar (replacing the scrolling tab strip), a fixed plan toolbar with overflow menu, a canvas that
  takes the remaining height, wrapping (not scrolling) contextual panels and a one-wall-at-a-time wall pager. Verified by
  a rendered test at 360 × 640 dp that finds no scrollable node. Research basis revised to mobile-only store reviews.
- E-011 (2026-10-27) **Owner request:** a test app to compare camera capture methods. Added `:lab` (separate app ID
  `com.owlacoustics.capturelab.dev`) with methods 1, 2 (model-free floor-line variant), 4, 5, 6 and 7 plus a
  tape-measure scorecard; method 3 paused by owner. Depth model: Depth Anything V2 Small int8 ONNX (Apache-2.0),
  downloaded at build time with checksum. arm64-v8a only. Portrait lock is intentional (tilt maths assumes upright).
